# Reviewed lifecycle and administrative recovery R1

23 October 2026. PT-06 restores all remaining non-secret intent types through the normal local workflows. Native file/review/application screens remain PT-07. [Full transfer plan](ONLINE_PENDING_TRANSFER_PLAN_R1.md).

`OnlineIntentRecovery` reads a validated inbox file and freezes one review ticket. The currently active account must match the file's canonical origin/account UUID; fresh authentication and current outlet membership are required. Original IDs are checked through the actor/outlet-scoped status endpoint. Already-recorded and locally-recovered references produce read-only results, without treating a possibly modified file payload as proof of the old receipt body. A missing result is snapshot-limited.

For a new action, the review contains the original payload/base and current role-dependent server data. Application rechecks the session, role, base, target and reference disposition against that review. Cancelled, stale, duplicate or account-switched callbacks cannot attach a different intent. It never invokes a server mutation. Later explicit synchronization still enforces server authorization, optimistic revisions, unique usernames and lifecycle state/generation rules.

Settings preserve name, timezone and cutoff against the newly reviewed settings revision. Team updates preserve target account, desired role/active flag against the freshly reviewed member revision. Team creation preserves username, display name and role, checks the authorized outlet roster and requires password entry in the normal account-creation flow. No password or password hash enters the file, Room payload, provenance or saved draft. Roster absence is not a claim that a username is globally available; the server retains its global uniqueness check.

Catalog recovery preserves the complete catalog business model as an EDITING draft. It must pass the normal edit/review/freeze/publication workflow. Normal catalog canonicalization retains UUIDs, sort orders, recipe relations and domain values; the original inbox bytes remain unchanged. Lifecycle recovery preserves action/reason, shows current state/generation/revision and attaches a new ordinary QUEUED action only when current role/state permit it. Incompatible role/state is displayed as blocked, not silently converted to a different action.

Room10 adds `online_recovered_admin`, combining the recovered non-secret pending operation and durable provenance in one row. The adapter presents active rows through the existing repository's settings/team/catalog APIs. Existing AtomicFile formats/readers are unchanged. If a file and recovered row occupy the same group, reads/attachment fail explicitly instead of choosing or overwriting a source. An acknowledgement or allowed dismissal archives the row; its original reference remains recognized after queue removal and process restart. This local record is not a server receipt.

Backup/count/account-switch/auth-recovery/own-team-access paths include recovered rows. Explicit export retains the complete normal pending values and new operation IDs, while leaving provenance and credentials out of the transport model. Frozen payload and sent-state guards match the normal workflows; catalog is editable only before freezing. Lifecycle provenance and its new action commit together in Room, with rollback if claim insertion fails. Quantity recovery also rejects references previously assigned to an administrative recovery.
